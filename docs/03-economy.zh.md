# 03 — 经济系统设计（微观经济学工程化）

> 英文版为主文档：[03-economy.md](03-economy.md)

> 目标：服务器经济不再靠服主拍脑袋。货币是可观测、可调控的系统。
> 原则：**先可观测，后可调控，最后才谈干预**。所有政策工具默认关闭、灰度开启。

## 1. 货币与账本

- 单一权威账本（复式记账，见 06），余额只是 `SUM(journal)` 的物化视图
- 多币种支持但 v1 只发一种基础币；"央行"= 服主角色账户
- 账户类型：PLAYER / TEAM / SYSTEM_SINK / SYSTEM_FAUCET / ESCROW（交易所保证金/贷款抵押）
- **货币身份：一种钱，两个名字。** `code`（如 `BRC`）是账本内部主键——分录行引用它，
  永不变更；`name`/`symbol` 是腐竹的展示皮：portal、Create 挂牌、聊天文案等一切玩家
  界面只渲染后者、绝不渲染 code。玩家之间走账户轨转账，这就是主流通轨，玩家间完全
  可交易。玩家感知不到"底层"，因为底层没有招牌——正如没人知道自己银行的准备金
  账户：code 是管道，钱是一种。若登记了可持形态（§8），它是**同一单位**的账本签名
  代币，经铸币窗口在账户与物品之间 1:1 存取——是存取款，不是兑换。没有第二种钱、
  没有平价、轨道上就没有格雷欣。

## 2. 货币供给观测（faucet/sink 全量记账）

每一分钱的诞生与毁灭都有分录，否则系统不可观测：

| Faucet（投放） | Sink（回收） |
|---|---|
| 任务/签到奖励、出售给系统商店、活动发放、铸币窗口兑付（§9） | 交易税、系统商店购买、传送费、拍卖行佣金、罚款、彩票、铸币费（§10） |

核心指标（每日物化到 `economy_daily`）：
- **M**（货币总量）= Σ 余额
- **净投放** = faucet − sink
- **货币流通速度 V** = 日交易额 / M（费雪方程 MV=PQ 的 V；V 骤降 = 通胀先行或信心崩塌）
- **基尼系数**（财富集中度；>0.8 时大户囤币会制造"人造通缩"）
- **入账率 banked share** = Σ 账户余额 /（账户 + 铸币窗口在外签发的可持代币）——
  货币供给有多少活在我们看得见的轨道上；可持形态只有登记过才存在（§8）
- **自足线（ALICE）**——观察户 Alice：口粮、床位租金（chunk ticket 摊销）、交通
  （距离×传送费）、最低可运行的 `machine_slot` 执照、基础工具耐久，一篮子最低
  成本开支；逐维度物化、月度链式更新。玩家在 §9 的共享周快照上三分类：自足 /
  ALICE / 赤贫，其中收入 = 劳动性净转入、**显式剔除 FAUCET 类入账**——救济金
  不算收入，否则瞄准器会污染自己的指标。基尼盯着上尾，Alice 盯着地板：鲸鱼
  噪声主导基尼，ALICE 份额对其天然稳健
- **村民普查**——按租户统计三个原版状态，见 docs/07 §7：在雇 / 预备
  （无业与傻子的繁殖翼）/ 冷链（僵尸村民）。是人头会计，不是福利会计——
  村民是稀缺、慢再生的资源

## 3. CPI（服务器物价指数）

- **篮子**：按"生存刚需 + 工业大宗 + 奢侈品"分层选 30~50 种物品（铁/圆石/火药/信标…），权重 = 过去 N 日该物品交易额占比（链式加权，权重月度重算）
- **价格源**：玩家间成交中位数（截尾均值防操纵）＞拍卖行成交＞系统商店挂价（仅参考）
- 公式：链式几何指数（Törnqvist 近似）。防操纵：单品单日权重上限、剔除可疑账户成交（联动 05 的异常检测）
- 发布：每日 CPI、7 日年化"通胀率"。游戏内告示牌可显示（Create Display Link，见 02）

## 4. 政策工具箱（全部参数化，存 `policy` 表，变更走审计）

| 工具 | 拧什么 | 治什么 |
|---|---|---|
| 交易税 / 拍卖佣金 | sink 强度 | 通胀、刷量洗单 |
| 系统商店买卖价差 | 做市商范围 | 给物价设"锚"，通缩时收窄价差放水 |
| faucet 日投放上限 | 货币发行 | 恶性通胀 |
| 动态传送费（按距离×CPI 因子） | 弹性 sink | 温和回收 |
| 大额持有税（超额累进，仅 SYSTEM 层） | 阆币成本 | 流动性陷阱、逼流通 |
| 持牌铸币费 + 兑付边距（§10） | 商品腿发行 | 村民大厅铸币漂移 |
| "公开市场操作"：央行账户反向挂单 | 供需 | 急性危机时的定向干预 |

调参纪律：一次只动一个旋钮，灰度 10% 交易，观察一周 CPI/V 再全量——**货币政策要有变更管理与回滚**（企业级，吃屎味最正的一集）。

## 5. 危机检测（规则先行，模型后置）

| 危机 | 信号 | 自动响应（默认仅告警） |
|---|---|---|
| 恶性通胀 | CPI 连续 7 日 > +2%/日 且 faucet 占比高 | 告警 + 建议收紧 faucet 上限 |
| 通缩螺旋 | CPI 连续 14 日 < −0.5%/日、V 下降、sink>faucet | 告警 + 建议收窄做市价差/发消费券（按 §2 Alice 做经济审查） |
| 需求脆弱 | ALICE 份额周环比上升而在就业人数持平 | 告警 + 复核发券瞄准——地板在物价指数注意到之前就已变薄（§2） |
| 挤兑（交易所/银行场景） | ESCROW 提现速率 > 历史 P99 ×3 | 熔断：限流 + 人工复核队列 |
| 流动性枯竭 | 订单簿深度 < 阈值且买卖价差走阔 | 告警 |
| 洗单/操纵 | 见 05（图检测：自成交环、对敲） | 标记 + 冻结复核 |

熔断器（circuit breaker）分级：L1 告警 → L2 限流 → L3 暂停该市场（人工解锁）。绝不静默干预——所有动作写公告，透明性就是货币政策的一部分。

## 6. 服务器物理资源商品化（"卖 TPS"，笑点即功能）

真实的稀缺资源管理，反而是本模块最有实用价值的部分：

- **计量**：每租户 chunk ticket 数、模拟距离开销、计划刻/漏斗吞吐占比（Agent 采集，Carpet 数据源见 02）
- **配额**：`quota(tenant, resource, limit, used)`——chunk ticket 上限、单区块实体上限等
- **计费**：超配额部分按分钟计费扣账本（这真的就是云厂商计费模型）
- **交易（P4+）**：租户间配额转让市场。通胀时期服主增发的是"算力券"而非货币——
  **CPU 时间是服务器央行真正的金本位锚**（此处应有笑声，但它是防虚拟通胀的硬锚）
- 红线：不与真实货币挂钩；免费额度必须保证基本玩法

## 7. 分期

P1 账本+观测（M/V/净投放/CPI 每日报表）→ P2 税/佣金/价差三个旋钮 → P3 熔断器 → P4 配额市场 → P5 交易所/期货（行为艺术封顶，期权建议永久封印，谢谢）。

## 8. 货币登记制与老牌插件兼容

- 账本只接受**已登记货币**（V8；BRC 预置，ACTIVE/RETIRED 状态）。腐竹在 web 控制台铸币——
  `POST /api/v1/currencies`。财务不能凭空造币，那是水龙头的职责。
- `PATCH /api/v1/currencies/{code}` 只许改展示皮（name/symbol/bearer_item_id）——code 不可变，
  分录引用它。给钱换招牌是品牌行为，不是货币政策（§1）。
- **可持形态是可选的**：`bearer_item_id`（V11；可空，空 = 纯账户币）。配置后，铸币窗口
  发放该物品的账本签名代币（persistent data tag + 序列号 = 签名）。标记代币是钱，
  同材质散货是商品——村民大厅产的是商品，永远不是钱（§10）。占位物品由腐竹自选：
  绿宝石是在编梗，金粒同理可用，登记表说了算。
- 老牌货币插件（Vault 系插件服、mod 经济）以**适配器镜像外币**方式接入：每种外币一个兑换账户，
  余额单向同步为对某登记币种的汇率。外部货币不经兑换分录永远变不成账本货币——镜像不稀释 M。
- 机器放置是**受许可行为**（配额资源 `machine_slot`）：算力额度是限制生电量产的经济杠杆。
  超配与高危区块（`chunk.performance` 遥测超阈值）通过 outbox **通知管理员**；
  怎么管是管理员的事，本系统设计上不做执行。

## 9. P3 反垄断：累进税率、配额上限与绿宝石-TPS 双本位

检测 -> 诊断 -> 处方。以下一切只在反垄断机制**激活**时上膛。

**机制激活带滞回**（断路器 half-open 家传手艺）：财富基尼 > 0.8 激活，
< 0.7 解除。0.7–0.8 之间保持原状态——单阈值附近抖动会让税开开关关，
玩家的体感就是抽风。

**一份周快照喂所有机制。** 基尼与流速 V 出自同一个周快照计算
（V = 名义交易量 / 平均持有余额，数据源为 TRANSFERRED/CRAFTED 遥测）。
两个机制共用一个数时必须共用计算——绝不各自算各自的，否则账目
开始跟自己都对不上。

**累进算力税——边际分档，两件工具分离。** 税就是税：以**绿宝石**计价、
缴入 SYSTEM_SINK（真实收缩流动性；每租户每分钟一条账本事件，幂等键
`tax:tenant:minute`；mspt 份额由 Agent 流量计体系计量并**按租户分钟聚合**——
采样流永不进账本）。按全服 mspt 份额边际分段计价：
0-20% @ 1.0x | 20-35% @ 1.2x | 35-50% @ 1.6x | >50% @ 2.5x。**没有悬崖**：
越档的每一个绿宝石按下一档税率计，像正经所得税——永远跑 49.9% 不再是
最优策略。

>50% 线**不是税率，是红线**。份额持续超过 50%（农场卡特尔的操作定义）
走既有管理员告警阶梯升级为 `BRP-0950`（告警族预留 `BRP-09xx`）。一件工具
不能既是税又是死刑：税单收绿宝石，红线页人类。**配额**保持纯数量工具
（硬顶、机器许可）——货币工具与数量工具永不拧在一起。

**累进财富税（货币侧辅助，机制门控）。** 余额分档：<=100万：0% |
<=1000万：0.5%/周 | >1000万：1.5%/周，V < 0.5（共用周快照）加征囤币附加。
税收 route 进 SYSTEM_SINK，净投放中以负数出现（烧掉，不是花掉）。

**绿宝石-TPS 双本位。** 单一本位是脆弱的：绿宝石随村民大厅工程膨胀，
算力随硬件进步变便宜。（前半句不再是气象了——§10 给大厅发了牌照。）
BRC 同时锚定两者：

- **绿宝石腿** — MC 原生商品锚。央行金库（物理守卫的储物区域）持有绿宝石
  储备；铸币窗口按 1 组绿宝石 <=> X BRC 兑付。
- **TPS 腿** — 硬物理锚（§6）：配额分钟是商品，Y BRC <=> Z 配额分钟。

锚价带吸收 ±5% 漂移；越带重定锚是**政策投票，走既有审批工作流**——
货币事务不开第三条治理通道，RFC P3 在这里没有豁免权。

**Gresham 检测器。** 腿按**支付轨道**定义（绿宝石计价 vs 配额计价的
ESCROW 兑付流），绝不按物品流动——且两条轨道**性质不同**：绿宝石轨道是
**消费货币**（有处可花的腿：下界合金、方块、经济真正在买的东西），配额
轨道是**工业货币**（生产资料——玩家多半囤着自己刷绿宝石用）。一条轨道
在流量占比上一边倒不是危机；那是星期二。信号是**行为性**的，对每条轨道
各自的移动基线测量：当前 7 天流量对自身 4 周移动平均。警报在工业腿吞吐
相对**自己的基线**崩塌、同时消费腿持平或增长时触发——花劣币、囤良币，
这才是 Gresham 的本义。绝对占比阈值在这里试过并已退役：它们每周都响，
理所当然。冷启动：历史不足基线周数时检测器保持沉默。处方不变：重定锚，
或弱腿暂时浮动。

**铸币次序（金库不许与账本漂移）。** 每次铸币一律 FAUCET 账本事件**先**
入账、物品**后**发放——@Compensable 补偿序正好管这种"账动钱不动"。

P3 交付物：滞回接线、共享周快照 job、边际税引擎（绿宝石计价、租户分钟
聚合）、BRP-09xx 告警族、铸币窗口 saga、Gresham 检测器、重定锚预案。

## 10. 村民大厅就是铸币厂——发牌照，别打架

村民交易大厅按游戏机制的汇率把农产品炼成绿宝石。放任不观测，商品腿就会
随玩家发明的任何生电工程一起膨胀——§9 把这件事写成了"脆弱性"。禁止交易
不在选项里：撤单违反"绝不静默干预"，还把货币问题升级成治安问题。企业级
的答案是**收编**：数量封顶、货币抽税、全量计量。**"村民圈养是受许可行为"**
（机器放置那句话，只是把被圈养的对象换了个更有圈养天赋的）。

**计量——两个新事件（契约行随 Agent mixin 同批落地）：**

- `merchant.trade`（TELEMETRY）——每笔完成的村民交易一条。挂点：
  `MerchantResultSlot#onTake` 外切 mixin ◆（玩家取走结果槽即交易完成；
  NeoForge 没有现成的 post-trade 事件 ◆，对照 1.21.1 javadoc 验证）。
  payload：村民实体 id、职业、offer、进出物品与数量、chunk key。与 AE2/Create
  的 machine probe（02 稿）是同一等采集活。
- `villager.cured`（TELEMETRY）——NeoForge 没有专门的治愈事件；挂点为
  `LivingConversionEvent.Post`（ZombieVillager → Villager）✅。治愈**不重置**
  职业与 offer——它只改声望折扣：永久、首轮最深（1.20.2 起不再叠加 ◆）。
  被治愈的图书管理员是套利资产，被治愈的收购岗职员毫无变化。这条事件接给
  05 稿做折扣取证，不接吞吐。

**归属。** 大厅所在区块 → 租户，经 chunk ticket 注册表（09 §3）。有票地块的
交易记在票主持名上。无主地块里冒出发币的村民，是事件单不是犯罪——与机器
超配同款流程：页管理员，执行由人（§8）。服主自己的大厅挂显式 `SYSTEM_MINT`
租户，不然 §2 的净投放会悄悄算歪。流浪商人除卖货外还带最多两个收购位
（干草块/烤马铃薯一类）✅——不是纯汇：这点稀有铸币也路由进 `SYSTEM_MINT`。

**限速器游戏机制早造好了，我们只是读数。** 每个 offer：每次补货一份库存
（收购类交易 ≈16 次），工位在岗时每日补货最多两次 ✅——铸币速度 =
库存 × 补货次数，`merchant.trade` 负责计数。offer 只掷一次：重掷仅在村民
首次交易之前有效，经验一到 offer 永久上锁 ✅。且大厅只收原料——成品装备
在任何交易表里都不是可收购品类 ✅，日铸币上限由游戏数据决定，不归玩家的
聪明才智管。

**两件工具，永不互拧**（§9 的宪法，原样套用）：

- 数量工具——既有配额桶新增资源 `villager`（0 = 不限量许可；`quota.exceeded`
  页管理员，人来管）；
- 货币工具——**铸币费**：对 `merchant.trade` 产出按租户**按天**聚合，
  每租户每天一条账本事件，幂等键 `tax:tenant:mint:day`。逐笔是采样流，
  采样流永不进账本——§9 的教训原句复用。与算力税同款：绿宝石计价、缴入
  SYSTEM_SINK，收缩的是商品腿的真实流动性。

**为什么这让经济学家的方程闭环。** 投放模型原来是 `dM/dt = I + m − burn`，
m（私挖）是唯一既测不准又控不住的项。收编之后 m 变成政策项：
m = θ·O_hall，O_hall 由事件计数，θ 是铸币窗口的兑付边距。"村民大厅工程"
不再是天气，变成了一张带水表的税则表。1932 年 Wörgl 的 Stamp Scrip 把贴水
这半边做对了，只是没能给印钞机装水表。我们给印钞机装水表。

**铸币厂的劳动力也上了账。** `merchant.trade` 自带村民实体 id；雇员状态、
岗位表、淘汰码与普查见 07 稿 §7。会计更正：村民不领工资——玩家为货物付给
他们的绿宝石到手即销毁 ✅。大厅是一张双向柜台：收购向铸币、售出向烧币，
任何报表里的"雇员收入"都是汇，不是薪酬。

交付物：mixin + 两条契约行（P2，与 WMS 适配器同批）、`villager` 配额资源、
`SYSTEM_MINT` 租户、铸币费聚合引擎（P3，装在算力税引擎旁边）、§4 新增
兑付边距 θ 旋钮。

## 11. 研究注记：环流的非平衡稳态

设计上的回路：服务器在上端开水龙头（福利、任务奖励、系统商店收购），竞价
在下端烧币（mspt 超额、算力税、铸币费、传送费）。每个单位要么在流通，要么
死在账本里。只要耗散随流通量 M 单调上升——街上钱多，竞价清算价就高——系统
就是浮球阀：水龙头 = 耗散的那个平衡点自稳定。

待观察性质（研究，不是工程，这里不设阈值）：

- 囤币把耗散曲线压平——§9 财富税是把 M 推回轨道的反窖藏弹簧，V < 0.5
  附加是弹性保险；
- 会择时竞价 floor 的投机者让系统围绕不动点振荡而非收敛；振荡的非平衡稳态
  还是稳态。官方失败模式，原话照抄："双本位制：按日程崩溃、带仪表盘——
  这本身就是产品。"
- 鲸鱼地板会压弹性；模型没把握的地方，§5 熔断保持仅告警。
