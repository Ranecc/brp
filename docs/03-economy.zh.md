# 03 — 经济系统设计（微观经济学工程化）

> 英文版为主文档：[03-economy.md](03-economy.md)

> 目标：服务器经济不再靠服主拍脑袋。货币是可观测、可调控的系统。
> 原则：**先可观测，后可调控，最后才谈干预**。所有政策工具默认关闭、灰度开启。

## 1. 货币与账本

- 单一权威账本（复式记账，见 06），余额只是 `SUM(journal)` 的物化视图
- 多币种支持但 v1 只发一种基础币；"央行"= 服主角色账户
- 账户类型：PLAYER / TEAM / SYSTEM_SINK / SYSTEM_FAUCET / ESCROW（交易所保证金/贷款抵押）

## 2. 货币供给观测（faucet/sink 全量记账）

每一分钱的诞生与毁灭都有分录，否则系统不可观测：

| Faucet（投放） | Sink（回收） |
|---|---|
| 任务/签到奖励、出售给系统商店、活动发放 | 交易税、系统商店购买、传送费、拍卖行佣金、罚款、彩票 |

核心指标（每日物化到 `economy_daily`）：
- **M**（货币总量）= Σ 余额
- **净投放** = faucet − sink
- **货币流通速度 V** = 日交易额 / M（费雪方程 MV=PQ 的 V；V 骤降 = 通胀先行或信心崩塌）
- **基尼系数**（财富集中度；>0.8 时大户囤币会制造"人造通缩"）

## 3. CPI（服务器物价指数）

- **篮子**：按"生存刚需 + 工业大宗 + 奢侈品"分层选 30~50 种物品（铁/圆石/火药/信标…），权重 = 过去 N 日该物品交易额占比（链式加权，权重月度重算）
- **价格源**：玩家间成交中位数（截尾均值防操纵）＞拍卖行成交＞系统商店挂价（仅参考）
- 公式：链式几何指数（Törnqvist 近似）。防操纵：单品单日权重上限、剔除可疑账户成交（联动 05 的异常检测）
- 发布：每日 CPI、7 日年化"通胀率"。游戏内告示牌可显示（Create Display Link，见 02）

## 4. 政策工具箱（全部参数化，存 `policy` 表，变更走审计）

| 工具 | 拧什么 | 治什么 |
|---|---|---|
| 交易税 / 拍卖佣金 | sink 强度 | 通胀、刷量洗单 |
| 系统商店买卖价差 | 做市商范围 | 给物价设"锚"，通缩时收窄价差放水 |
| faucet 日投放上限 | 货币发行 | 恶性通胀 |
| 动态传送费（按距离×CPI 因子） | 弹性 sink | 温和回收 |
| 大额持有税（超额累进，仅 SYSTEM 层） | 阆币成本 | 流动性陷阱、逼流通 |
| "公开市场操作"：央行账户反向挂单 | 供需 | 急性危机时的定向干预 |

调参纪律：一次只动一个旋钮，灰度 10% 交易，观察一周 CPI/V 再全量——**货币政策要有变更管理与回滚**（企业级，吃屎味最正的一集）。

## 5. 危机检测（规则先行，模型后置）

| 危机 | 信号 | 自动响应（默认仅告警） |
|---|---|---|
| 恶性通胀 | CPI 连续 7 日 > +2%/日 且 faucet 占比高 | 告警 + 建议收紧 faucet 上限 |
| 通缩螺旋 | CPI 连续 14 日 < −0.5%/日、V 下降、sink>faucet | 告警 + 建议收窄做市价差/发消费券 |
| 挤兑（交易所/银行场景） | ESCROW 提现速率 > 历史 P99 ×3 | 熔断：限流 + 人工复核队列 |
| 流动性枯竭 | 订单簿深度 < 阈值且买卖价差走阔 | 告警 |
| 洗单/操纵 | 见 05（图检测：自成交环、对敲） | 标记 + 冻结复核 |

熔断器（circuit breaker）分级：L1 告警 → L2 限流 → L3 暂停该市场（人工解锁）。绝不静默干预——所有动作写公告，透明性就是货币政策的一部分。

## 6. 服务器物理资源商品化（"卖 TPS"，笑点即功能）

真实的稀缺资源管理，反而是本模块最有实用价值的部分：

- **计量**：每租户 chunk ticket 数、模拟距离开销、计划刻/漏斗吞吐占比（Agent 采集，Carpet 数据源见 02）
- **配额**：`quota(tenant, resource, limit, used)`——chunk ticket 上限、单区块实体上限等
- **计费**：超配额部分按分钟计费扣账本（这真的就是云厂商计费模型）
- **交易（P4+）**：租户间配额转让市场。通胀时期服主增发的是"算力券"而非货币——
  **CPU 时间是服务器央行真正的金本位锚**（此处应有笑声，但它是防虚拟通胀的硬锚）
- 红线：不与真实货币挂钩；免费额度必须保证基本玩法

## 7. 分期

P1 账本+观测（M/V/净投放/CPI 每日报表）→ P2 税/佣金/价差三个旋钮 → P3 熔断器 → P4 配额市场 → P5 交易所/期货（行为艺术封顶，期权建议永久封印，谢谢）。

## 8. 货币登记制与老牌插件兼容

- 账本只接受**已登记货币**（V8；BRC 预置，ACTIVE/RETIRED 状态）。腐竹在 web 控制台铸币——
  `POST /api/v1/currencies`。财务不能凭空造币，那是水龙头的职责。
- 老牌货币插件（Vault 系插件服、mod 经济）以**适配器镜像外币**方式接入：每种外币一个兑换账户，
  余额单向同步为对某登记币种的汇率。外部货币不经兑换分录永远变不成账本货币——镜像不稀释 M。
- 机器放置是**受许可行为**（配额资源 `machine_slot`）：算力额度是限制生电量产的经济杠杆。
  超配与高危区块（`chunk.performance` 遥测超阈值）通过 outbox **通知管理员**；
  怎么管是管理员的事，本系统设计上不做执行。

## 9. P3 反垄断：累进税率、配额上限与绿宝石-TPS 双本位

检测 -> 诊断 -> 处方。以下一切只在反垄断机制**激活**时上膛。

**机制激活带滞回**（断路器 half-open 家传手艺）：财富基尼 > 0.8 激活，
< 0.7 解除。0.7–0.8 之间保持原状态——单阈值附近抖动会让税开开关关，
玩家的体感就是抽风。

**一份周快照喂所有机制。** 基尼与流速 V 出自同一个周快照计算
（V = 名义交易量 / 平均持有余额，数据源为 TRANSFERRED/CRAFTED 遥测）。
两个机制共用一个数时必须共用计算——绝不各自算各自的，否则账目
开始跟自己都对不上。

**累进算力税——边际分档，两件工具分离。** 税就是税：以**绿宝石**计价、
缴入 SYSTEM_SINK（真实收缩流动性；每租户每分钟一条账本事件，幂等键
`tax:tenant:minute`；mspt 份额由 Agent 流量计体系计量并**按租户分钟聚合**——
采样流永不进账本）。按全服 mspt 份额边际分段计价：
0-20% @ 1.0x | 20-35% @ 1.2x | 35-50% @ 1.6x | >50% @ 2.5x。**没有悬崖**：
越档的每一个绿宝石按下一档税率计，像正经所得税——永远跑 49.9% 不再是
最优策略。

>50% 线**不是税率，是红线**。份额持续超过 50%（农场卡特尔的操作定义）
走既有管理员告警阶梯升级为 `BRP-0950`（告警族预留 `BRP-09xx`）。一件工具
不能既是税又是死刑：税单收绿宝石，红线页人类。**配额**保持纯数量工具
（硬顶、机器许可）——货币工具与数量工具永不拧在一起。

**累进财富税（货币侧辅助，机制门控）。** 余额分档：<=100万：0% |
<=1000万：0.5%/周 | >1000万：1.5%/周，V < 0.5（共用周快照）加征囤币附加。
税收 route 进 SYSTEM_SINK，净投放中以负数出现（烧掉，不是花掉）。

**绿宝石-TPS 双本位。** 单一本位是脆弱的：绿宝石随村民大厅工程膨胀，
算力随硬件进步变便宜。BRC 同时锚定两者：

- **绿宝石腿** — MC 原生商品锚。央行金库（物理守卫的储物区域）持有绿宝石
  储备；铸币窗口按 1 组绿宝石 <=> X BRC 兑付。
- **TPS 腿** — 硬物理锚（§6）：配额分钟是商品，Y BRC <=> Z 配额分钟。

锚价带吸收 ±5% 漂移；越带重定锚是**政策投票，走既有审批工作流**——
货币事务不开第三条治理通道，RFC P3 在这里没有豁免权。

**Gresham 检测器。** 腿按**支付轨道**定义（绿宝石计价 vs 配额计价的
ESCROW 兑付流），绝不按物品流动——对 ESCROW 流水做 7 天滑窗聚合即可。
单腿占比 > 95% 为一等危机信号（§5）；处方：重定锚，或弱腿暂时浮动。

**铸币次序（金库不许与账本漂移）。** 每次铸币一律 FAUCET 账本事件**先**
入账、物品**后**发放——@Compensable 补偿序正好管这种"账动钱不动"。

P3 交付物：滞回接线、共享周快照 job、边际税引擎（绿宝石计价、租户分钟
聚合）、BRP-09xx 告警族、铸币窗口 saga、Gresham 检测器、重定锚预案。
