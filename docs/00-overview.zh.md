# 00 — 愿景与边界

> 英文版为主文档：[00-overview.md](00-overview.md)

## 一句话

BRP 把 Minecraft 服务器的资源管理做成一套**多租户 ERP**：
经济是财务模块，仓库/AE2/Create 库存是 WMS，配方是 BOM，农场和机器是产能，红石是 IO 总线。

## 术语表（企业级黑话对照）

| 术语 | 游戏含义 | 企业黑话 |
|---|---|---|
| Tenant（租户） | 公会 / 团队 / 生电小组 | tenant_id 贯穿所有表，行级隔离 |
| Ledger | 服务器货币账本 | 复式记账、append-only、可审计 |
| Stock | 箱子/AE2 ME 网络/Create 物品柜里的东西 | WMS 库存快照 |
| BOM | 配方树（64 TNT → 火药+沙） | 物料清单展开 |
| Work Order | "帮我采 10 组沙子" 派给成员 | 工单，可审批 |
| Capacity | 农场产出速率（items/h）、机器 SU/转速 | 产能 / 设备负载 |
| Signal | 无线红石频道（0-15 模拟量） | IO 信号总线 |
| Flow Meter | 卡在物流路径上的计数方块 | 计量点 / SCADA 探针 |
| Quota | 每队 chunk ticket / 机器数量上限 | 资源配额（卖 TPS 的地方，见 03） |

## 角色与信任边界

**一个通用 mod jar**（单文件安装），运行时决定启动什么：
装在专用服务器上 = Agent 运行时；装在玩家客户端上 = UI 运行时。

```
玩家客户端(不可信) ──► MC 专用服务器 [BRP-Agent(可信)] ──HTTPS/HMAC──► BRP-Backend(权威)
        │                                                        ▲
        └──────────── Web 门户 / OAuth2 登录（只读+发起请求）────────┘
```

铁律：
1. **客户端 mod 永远不直接写状态**，只能发起请求与读报表。
2. **Agent 是唯一游戏侧数据来源**，但 Backend 对其上报仍做范围/速率校验（Agent 进程可能被魔改）。
3. **Backend 是账本与库存快照的唯一权威**；游戏内余额只是缓存展示。

## 明确不做（Non-goals）

- 不做权限插件替代品（对接 LuckPerms，不自建权限模型执行）
- 不做第一版反作弊（异常检测先做"标记+复核"，不自动处罚，见 05）
- 不做 Forge/Fabric 双加载器出包（Create 锁定 NeoForge，见 02）
- 不在游戏进程里跑 Spring（类加载地狱 + 崩溃耦合，见 01）
- P5 之前不做真实货币相关的一切功能
