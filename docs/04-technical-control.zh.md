# 04 — 生电计量与控制

> 英文版为主文档：[04-technical-control.md](04-technical-control.md)

> 生电（technical MC）玩家的核心诉求：农场是资产，产出是现金流，卡转是事故。
> BRP 把"农场"建模为一等公民：**计量 → 归因 → 控制 → 优化**。

## 1. 农场即资产（Farm Registry）

一个"农场"= 一组注册到 BRP 的资源：
```
farm = {
  tenant, name, region(区块集),
  meters:   [FlowMeter#1, ...],        // 计量点
  cutoff:   SignalChannel("farm_x/off"),// 总闸
  output:   [iron_ingot, ...],          // 产出物品
  quota:    {onhand_max: 27648n},       // 库存上限策略
}
```

## 2. 计量（Metering）

- **流量计 Flow Meter**：卡在物流路径（漏斗链/管道首末）的计数方块，按物品 ID 累计通过量；
  采样窗口聚合（10s/1min/1h）后批量上报 → `throughput` 时序（TimescaleDB，P2 引入，先落 PG 分区表）
- **产能 = EWMA(速率)** 而非瞬时值，抗抖动；产出异常下跌 >50% 且持续 = **"农场卡转"告警**（推 Discord）
- **ME 桥 / Create 物品柜**：库存增量本身也是计量源（不装流量计也能算净产出）
- 假人农场（Carpet）：假人不产生玩家事件，但流量计在路径上照样计数 → 计量与在线人数解耦 ✔

## 3. 控制（Control）

- **总闸**：农场注册时绑定一个信号频道；Agent 收到 `signal.set(channel, level)` → 实体红石切断农场时钟/发射器供电
- **策略引擎**（Backend 下发，Agent 本地执行，零延迟生效）：
  - 库存上限：`iron_onhand >= quota` → 自动置 15（停农场）；降至 80% → 归零（复产）。**这就是生电版的 min/max 补货策略**
  - 定时窗：只在服务器低峰时段全开（配合 TPS 配额，见 03）
  - 互锁：多农场共享一个总闸（防止同时全开压垮 TPS）——**生电版的错峰调度**
- **模拟量输出**：频道 0-15 映射库存水位/价格指数 → 红石比较器读取 → 生电玩家直接拿红石算逻辑（原汁原味）

## 4. 与生电社区的相处之道（产品原则）

1. **永不绕过玩家的红石**：我们只提供"总闸"这个原语，怎么用是玩家的事
2. **可编程接口优先**：CC:T peripheral（02 §4）让技术玩家用 Lua 把 BRP 编进自己的系统，而不是被我们的 UI 锁死
3. **计量透明**：任何人可查自己租户的全部原始数据（导出 CSV/JSON）
4. 性能红线：Agent 每世界 tick 采集开销预算 < 0.1ms（无锁快照 + 批处理，见 01 §5）

## 5. 阶段

P2：流量计 + 农场注册 + 产能日报 + 卡转告警  
P3：库存上限自动总闸（min/max）  
P4：错峰调度（TPS 配额联动）+ 产能预测进 MRP/APS
